# Group 4 collaboration

Continue using https://github.com/JJJelena/Hotel-Cancellation-Group4. Updates are new commits in the same repository; a new repository is unnecessary.

## Invite teammates

1. The owner opens the repository on GitHub and chooses **Settings**.
2. Under **Access**, choose **Collaborators**, then **Add people**.
3. Enter each teammate's GitHub username, select the matching account, and send the invitation.
4. The teammate accepts the GitHub/email invitation and clones the repository using their own account.

Do not share passwords. The owner must send invitations; this package does not add accounts automatically.

## Work together in GitHub Desktop

1. Before editing, choose **Fetch origin** and **Pull origin** if offered.
2. Choose **Current branch → New branch**, for example `b-clustering-fix`.
3. Edit the appropriate files. For an existing notebook or figure, replace the file at the same relative path.
4. Review **Changes**, write a precise summary, and choose **Commit to ...**.
5. Choose **Publish branch** the first time, or **Push origin** later.
6. Open a pull request against `main`; another member reviews the changed files and results before merging.
7. Everyone switches to `main` and fetches/pulls the merged version before the next change.

Small text changes can also use GitHub's file edit button on a branch. Notebook edits and binary figures are easier locally. Assign a member to integrate shared report/README files to reduce conflicting edits. Changes on one computer are not online until pushed. A commit on `main` may first display **Publish branch** before **Push origin**.

Official instructions: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository
